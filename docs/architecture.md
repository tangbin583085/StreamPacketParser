# 架构说明

核心库不依赖串口、TCP、USB、BLE或任何UI框架。传输层只需要把收到的字节片段按顺序交给 `PacketParser`。

一次解析大致经过下面几步：

1. 把新的字节片段追加到有上限的内部缓存。
2. 查找配置中的帧头。
3. 如果暂时找不到完整帧头，保留末尾可能构成帧头的那一小段。
4. 数据足够时读取无符号长度字段。
5. 使用checked运算计算完整帧长度，并检查最小值和最大值。
6. 数据不够就等待下一次 `Append`；数据足够则复制出候选帧。
7. 调用 `IFrameValidator` 校验候选帧，成功后返回 `ParsedPacket`，失败后返回诊断。
8. 对被拒绝的数据向后移动一个字节，继续寻找后续帧头。

内部缓存使用可扩容的 `byte[]`，通过读写索引避免频繁移动整个数组。只有在后续追加需要空间时才会压缩已经消费的前缀；一次传入很大的数据也会按 `MaxBufferedBytes` 分段处理。

返回的数据包拥有独立数组，后续追加或缓存压缩不会改变已经交给调用方的内容。

帧头搜索使用运行时的 Span搜索。对 `n` 个缓存字节和 `m` 字节帧头，保守复杂度为 `O(n * m)`；常见的两字节或四字节帧头基本按输入长度线性处理。解析循环中的每条路径都会等待更多数据、丢弃数据或产出数据，不会原地空转。
